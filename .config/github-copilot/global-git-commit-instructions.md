# Commit Message Convention

Always write commit messages following the **Conventional Commits** convention:

`<type>(<scope>): <short description in lowercase>`

### Allowed types:
- **feat**: for new features.
- **fix**: for bug fixes.
- **docs**: for changes in documentation.
- **style**: for formatting changes that do not affect logic.
- **refactor**: for code changes that neither fix bugs nor add features.
- **perf**: for performance improvements.
- **test**: for adding or correcting tests.
- **chore**: for maintenance tasks.

### Rules:
1. The description line must not exceed **72 characters**.
2. **Do not use a period** at the end of the first line.
3. Use the **English** language.
4. After the first line, you can add a **body** separated by a blank line explaining the reason for the change.
